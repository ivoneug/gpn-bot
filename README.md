# gpn-bot

Telegram-бот, который следит за наличием топлива на АЗС «Газпромнефти» и пишет, как только
нужное топливо появилось (или закончилось).

По умолчанию отслеживает две АЗС в Краснодаре и три вида топлива:

| АЗС | id | Топливо |
|---|---|---|
| Селезнева, 197/2 (АЗС №1) | 885 | АИ-92 (id 62), АИ-95 (id 12), G-95 (id 421) |
| Уральская, 194/1 (АЗС №2) | 886 | АИ-92 (id 62), АИ-95 (id 12), G-95 (id 421) |

Источник данных и разбор API — в [RESEARCH.md](RESEARCH.md).

## Как это работает

Раз в 7 минут (настраивается) бот дёргает `POST https://gpnbonus.ru/api/stations/list` — тот же
эндпоинт, что и карта на сайте. Ответ содержит все АЗС страны с полем `oils`, где по каждому виду
топлива стоит флаг «есть/нет» в реальном времени. Отбор нужных АЗС делается на своей стороне:
серверных фильтров у эндпоинта нет.

Правила отправки:

- **бот пишет о каждом изменении сразу** — на первом же опросе, где флаг сменился; ни подтверждений, ни пауз между сообщениями нет;
- первый в жизни опрос задаёт базовую линию и уведомлений не шлёт;
- если API недоступен дольше `STALE_ALERT_MIN` минут, бот сам предупредит, что данные протухли —
  чтобы тишина не читалась как «топлива нет». О восстановлении связи тоже напишет.

Состояние (подписчики и подтверждённые значения) лежит в `state.json` и переживает перезапуск.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | подписаться на уведомления |
| `/stop` | отписаться |
| `/status` | текущее наличие по отслеживаемым АЗС |
| `/find <запрос>` | найти АЗС по городу или адресу и узнать её id |
| `/help` | справка |

## Где развёрнуто

OrangePi 3 (`orangepi@192.168.1.123`, Ubuntu 24.04, aarch64), каталог `~/gpn-bot`, бот `@gpn_Info_bot`.

На этой машине пользователь не состоит в группе `docker`, поэтому **все команды идут через `sudo`**:

```bash
cd ~/gpn-bot && sudo docker compose logs -f
```

Автозапуск обеспечивается связкой `systemctl enable docker` (включено) + `restart: unless-stopped`
у контейнера. Проверено перезапуском демона: контейнер поднимается сам и подхватывает состояние из тома.

Обновить после правок (с рабочей машины):

```bash
tar czf /tmp/gpn-bot.tgz --exclude node_modules --exclude .git --exclude data --exclude docs . && scp /tmp/gpn-bot.tgz orangepi@192.168.1.123:/tmp/ && ssh -t orangepi@192.168.1.123 'tar xzf /tmp/gpn-bot.tgz -C ~/gpn-bot && find ~/gpn-bot -name "._*" -delete && cd ~/gpn-bot && sudo docker compose up -d --build'
```

## Запуск в Docker (VPS)

```bash
git clone <repo> gpn-bot && cd gpn-bot
cp .env.example .env
# впиши BOT_TOKEN, при желании поправь список АЗС и топлива
docker compose up -d --build
```

Логи и управление:

```bash
docker compose logs -f
```

```bash
docker compose restart
```

Состояние живёт в именованном томе `gpn-bot-data`. Посмотреть:

```bash
docker compose exec gpn-bot cat /app/data/state.json
```

Обновление после `git pull`:

```bash
docker compose up -d --build
```

Контейнер работает не от root (пользователь `node`), логи ротируются (10 МБ × 3),
политика перезапуска — `unless-stopped`.

## Запуск без Docker

Нужен Node.js 20+ (используется встроенный `fetch`).

```bash
npm ci --omit=dev
cp .env.example .env
npm run dev
```

`npm run dev` подхватывает `.env` через `--env-file-if-exists`. В проде (`npm start`) переменные
берутся из окружения.

## Настройки

Все — через переменные окружения, полный список с комментариями в [.env.example](.env.example).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен от [@BotFather](https://t.me/BotFather), обязателен |
| `TRACKED_STATIONS` | `885,886` | id АЗС через запятую |
| `TRACKED_FUELS` | `62,12,421` | id видов топлива через запятую |
| `POLL_INTERVAL_SEC` | `420` | интервал опроса, минимум 60 |
| `POLL_JITTER_PCT` | `10` | случайный разброс интервала |
| `NOTIFY_ON_GONE` | `true` | писать ли, когда топливо закончилось |
| `STALE_ALERT_MIN` | `60` | через сколько молчания API предупредить о протухших данных |
| `ALLOWED_USER_IDS` | пусто | белый список telegram user id; пусто = бот открыт всем |
| `STATE_FILE` | `./data/state.json` | файл состояния |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |

### Как добавить ещё АЗС

1. В боте: `/find Краснодар` (или по адресу — `/find Селезнева`).
2. Взять `id` из ответа, дописать в `TRACKED_STATIONS`.
3. `docker compose up -d` — перезапуск подхватит новый список.

Ходовые id топлива: `62` = АИ-92, `12` = АИ-95, `421` = G-95, `100032` = G-100, `372` = ДТл,
`373` = ГАЗ. Полный справочник — в [RESEARCH.md](RESEARCH.md).

```
  messages.js  форматирование сообщений
  logger.js    логи
```

## Известные ограничения

- Эндпоинт отдаёт весь список АЗС страны (~165 КБ с gzip) — фильтров по региону у него нет.
  При интервале в 7 минут это ~35 МБ трафика в сутки.
- У части АЗС API вообще не отдаёт наличие (`oils` приходит пустым) — такие бот пропускает
  и пишет об этом в `/status`.
- Сайт отвечает 403 на «безликие» User-Agent, поэтому клиент представляется десктопным Chrome.
- Официального API нет, всё держится на эндпоинте карты — он может измениться без предупреждения.
